# Yappr Data Contracts

Dash Platform data contracts used by the Yappr dapp. The JSON here is the
source of record for what was registered; deployed contract ids live in
`lib/constants.ts` (testnet defaults) and the `.env.*` files (per-deployment
overrides).

## Social contract

| File | Status |
|------|--------|
| `yappr-social-contract-v2.json` | **Deployed** on testnet (`9oDC6xdg…`, staging/prod). 16 document types + the YAPP token. Topology `v2`: replies chain through a polymorphic `parentId`; like/repost/bookmark/quote share one `postId` keyspace. The on-chain copy has since gained the optional `post.embedContractId`/`embedDocType`/`embedId` fields via `scripts/update-social-contract.mjs`, and its YAPP token carries `keepsHistory` (transfer/freeze/mint/burn/pricing/purchase, all true — verified on chain 2026-09-18) which this file predates; `lib/contracts/bundled/testnet.json` is the faithful snapshot. |
| `yappr-social-contract-v4.json` | **Superseded** by v5 on the moutai devnet, kept as the input `scripts/build-v5-contract.py` transforms. The v3 interaction topology (flat threads, `likeReply`, posts-only repost/bookmark, dual quote fields, `refersTo` everywhere) plus the like overhaul: indexOnly `like`/`likeReply`, inline `post.hashtag` (`''` = untagged), poster-attested `author` fields. Needs protocol v14. |
| `yappr-social-contract-v5.json` | **Superseded** by v6 on the moutai devnet (was `BQrC6mu3…`), generated by `scripts/build-v5-contract.py` from the v4 file. v4 plus the dev.7 aggregate-index grammar: `hashtag` optional (61-char ceiling, the `''` sentinel dies), `skipIfAbsent` on `byHashtagPost`, rankedCountable at-forms for trending tags and the creator leaderboard, a plain `byAuthorTimePost` sibling, and the ranked follow chain. Needs protocol v14 on 4.2.0-dev.7. |
| `yappr-social-contract-v6.json` | **Deployed** on the moutai devnet (`HWZdaqfP…`, the /devnet build), generated by `scripts/build-v6-contract.py` from the v5 file. v5 plus the windowed rankings: daily and rolling like/beat indexes with a seven-day TTL and the `beat` doctype. See `docs/V6_WINDOWED_RANKINGS.md`. |

The topology differences are wired into the app through
`lib/contract-topology.ts` and selected per deployment with
`NEXT_PUBLIC_CONTRACT_TOPOLOGY`.

Historical drafts (`-actual`, `-clean`, `-ready`, `-deploy`, `-updated`,
`-v3-draft`, `-v3-topology`, and the unsuffixed original) were removed
2026-08-31; recover them from git history if ever needed.

## Feature contracts

- `yappr-profile-contract.json` — unified profile contract (avatar/banner live here, not in the social contract)
- `yappr-dm-contract.json` — encrypted direct messages (v3, testnet: `conversationInvite`, `directMessage`, `readReceipt`)
- `yappr-dm-contract-v4.json` — **deployed on moutai** (`BSLkjKCb…`): v3 plus exactly two additive flags — `countable` + `rangeCountable` on `directMessage.conversation`, so unread is a count query instead of a 100-message download, and `refersTo: {type: identity}` on `conversationInvite.recipientId`. No token costs, no ranked/timeRange indexes, no indexOnly rewrite: DMs stay cheap. Built by `scripts/build-dm-v4-contract.py`, verified by `scripts/verify-dm-v4.mjs`; see `docs/DM_V4.md`
- `yappr-blog-contract.json` — long-form blog posts, comments, follows (v1, testnet)
- `yappr-blog-contract-v2.json` — **deployed on moutai** (`4pSFqC9Q…`): v1 plus a poster-attested `blogPost.author`, the refersTo chain (post→blog, comment→post with a `blogPostOwnerId` agreement, follow→blog), countable/ranked comment and follower trees, a daily-grid `followersByDay`, and YAPP-priced comments. Built by `scripts/build-blog-v2-contract.py`, verified by `scripts/verify-blog-v2.mjs`; see `docs/BLOG_V2.md`
- `yappr-storefront-contract.json` — stores, items, orders, reviews, shipping (v1, testnet)
- `yappr-storefront-contract-v2.json` — **deployed on moutai** (`57k7LnhQ…`): v1 plus proved rating averages/rankings, item reviews, refersTo chain, countable orders, YAPP-priced reviews. Built by `scripts/build-storefront-v2-contract.py`, verified by `scripts/verify-storefront-v2.mjs`; see `docs/STOREFRONT_V2.md`
- `yappr-vault-contract.json` — contract-bound encryption keys + encrypted storage
- `yappr-auth-vault-contract.json` — auth vault + access grants
- `encrypted-key-backup-contract.json` — passphrase-encrypted key backups
- `key-exchange-v2.json` — QR login key-exchange protocol (deployed everywhere). An indexOnly + TTL re-cut was built and measured 2026-09-18: 42% more credits per response (93.8M vs 66.3M) because the payload must stay in a permanent index, so it was dropped; see `docs/NON_SOCIAL_OPPORTUNITIES.md`
- `pollr-contract-v3.json` — polls (deployed on testnet, externally owned); `pollr-contract-v2.json` is the abandoned predecessor, kept for the on-chain id record
- `pollr-contract-v4.json` — **deployed on moutai** (`HRuWcjcG…`): v3 plus a poster-attested `poll.author`, a permanent poll, indexOnly `vote`/`multiVote` whose mode rule is structural rather than a `unique` index, preallocated ballot trees, and the ranked winner query. Built by `scripts/build-pollr-v4-contract.py`, verified by `scripts/verify-pollr-v4.mjs`; see `docs/POLLR_V4.md`. The standalone Pollr repo needs the same cut before a shared testnet v4 exists
